# Кузня Модов

Сайт для загрузки, описания и распространения модов к играм. Node.js + Express + SQLite,
без внешних баз данных и без обязательной регистрации пользователей.

## Что уже есть

**Для игроков**
- Каталог модов с обложками, поиском, фильтром по игре, сортировкой (новые / обновлённые / по скачиваниям / по лайкам / по алфавиту) и тег-чипами.
- Страница мода: галерея скриншотов с лайтбоксом, описание, история версий с changelog, скачивание, лайки, комментарии, кнопка «Пожаловаться».
- Блок «Витрина» на главной — моды, отмеченные администратором как избранные.
- Живая статистика на главной (кол-во модов, игр, скачиваний).

**Для разработчиков модов (без регистрации)**
- Переключатель режима «Игрок / Разработчик» в шапке (просто локальный выбор, ничего не требует вводить).
- Форма загрузки: игра, название, версия, автор, теги, описание, обложка, до 8 скриншотов, файл мода (архив).
- После публикации выдаётся **уникальный код управления модом** — без регистрации это единственный способ подтвердить, что мод ваш. Код показывается один раз и автоматически сохраняется в браузере, где мод был создан.
- Страница «Управление модом»: редактирование описания/тегов/обложки/скриншотов, публикация новой версии файла с changelog (ведётся история версий), удаление мода — всё по коду управления (или из-под администратора).

**Плюс по мелочи**
- Rate limiting на логин и на запросы записи (защита от спама и подбора пароля) — лайки и скачивания из-под лимита выведены отдельно, чтобы не мешать активному использованию.
- Валидация типов файлов (изображения отдельно, архивы модов отдельно) и лимиты размера — настраиваются в `.env`.
- helmet для базовых заголовков безопасности, express-session с httpOnly cookie.
- Не требует внешней СУБД — всё хранится в SQLite-файле, бэкап сайта = скопировать `data/` и `uploads/`.
- **Сборки модов** — можно объединить несколько (от двух) опубликованных модов одной игры в один набор со своим описанием, обложкой и тегами. Публикуется и управляется так же, как мод — без регистрации, по коду управления. Страница сборки показывает все входящие моды и кнопку «Скачать все».
- **Жалобы — это переписка, а не разовая форма.** После отправки жалобы у заявителя открывается чат с администрацией прямо на сайте (доступ по токену, сохранённому в браузере); администратор отвечает из своей панели, оба видят историю сообщений.
- **Роли администраторов.** Главный администратор (владелец, из `.env`) может заводить дополнительных администраторов прямо на сайте — они модераторы: отвечают на жалобы, удаляют нарушающие моды и сборки, но не могут управлять играми, витриной или другими администраторами.

## Установка локально

```bash
git clone <ваш-репозиторий> modforge
cd modforge
npm install
cp .env.example .env
# откройте .env и задайте SESSION_SECRET, ADMIN_USERNAME, ADMIN_PASSWORD
npm start
```

Сайт поднимется на `http://localhost:3000`. Скрытая кнопка входа админа — шестерёнка в подвале страницы.

Если нужно сменить пароль админа из консоли (например, забыли пароль):

```bash
node server/utils/create-admin.js admin новый-пароль
```

## Деплой на VPS (Ubuntu/Debian, пример)

1. **Установите Node.js 18+ и pm2:**
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
   sudo apt-get install -y nodejs
   sudo npm install -g pm2
   ```

2. **Скопируйте проект на сервер и установите зависимости:**
   ```bash
   git clone <ваш-репозиторий> /var/www/modforge
   cd /var/www/modforge
   npm install --omit=dev
   cp .env.example .env
   nano .env   # задайте SESSION_SECRET, ADMIN_USERNAME, ADMIN_PASSWORD, COOKIE_SECURE=true
   ```

3. **Запустите через pm2** (автоперезапуск при падении и после ребута сервера):
   ```bash
   pm2 start ecosystem.config.js
   pm2 save
   pm2 startup   # выполните команду, которую покажет pm2
   ```

4. **Настройте Nginx как обратный прокси** — пример конфига в `deploy/nginx.conf.example`.
   Скопируйте, поправьте домен, включите сайт и перезапустите nginx.

5. **Подключите HTTPS** (рекомендуется, особенно раз есть форма логина админа):
   ```bash
   sudo apt install certbot python3-certbot-nginx
   sudo certbot --nginx -d your-domain.example
   ```
   После этого поставьте `COOKIE_SECURE=true` в `.env` и перезапустите: `pm2 restart modforge`.

6. **Бэкапы.** Всё состояние сайта — это папки `data/` (база SQLite) и `uploads/` (файлы модов, обложки, скриншоты). Регулярно архивируйте обе:
   ```bash
   tar -czf modforge-backup-$(date +%F).tar.gz data uploads
   ```

## Структура проекта

```
mods-site/
  server/
    server.js          — точка входа Express
    db.js               — схема SQLite и инициализация

    routes/mods.js        — CRUD модов, версии, скачивания, лайки, комментарии, жалобы
    routes/admin.js       — логин админа, статистика, модерация
    utils/upload.js       — настройка multer (лимиты, типы файлов)
    utils/create-admin.js — консольный скрипт создания/сброса админа
  public/
    index.html, mod.html, upload.html, edit.html, admin.html, 404.html
    css/style.css
    js/app.js  — общие утилиты (API-клиент, тосты, шапка/подвал, роль, токены)
    js/home.js, mod.js, upload.js, edit.js, admin.js
  uploads/    — загруженные файлы (создаётся автоматически)
  data/       — файл базы данных SQLite (создаётся автоматически)
  deploy/nginx.conf.example
  ecosystem.config.js  — конфиг pm2
```

## Важно про безопасность модели без регистрации

Так как разработчики не регистрируются, право редактировать/удалять мод подтверждается
секретным **кодом управления**, который выдаётся один раз при публикации. Это осознанный
компромисс ради простоты — если код потерян, восстановить его может только администратор
(вручную через панель — можно скрыть/удалить мод, но не подставить чужой код). Если в
будущем понадобятся полноценные аккаунты разработчиков, это отдельная фича поверх
текущей схемы БД (таблица `mods` уже разделяет «кто может управлять» от «кто автор»).
